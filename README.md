# FogNest
Dream nests in fog — An AI RAG powered San Francisco home finder app.

Built with **LangChain**, **LangGraph**, **Pinecone**, and **OpenAI**.

Listing data lives in a CSV file. Each listing has a `listing_description` column —
free-text written by the listing agent — which often contains richer detail than structured
fields alone. The app runs a **three-signal hybrid retrieval** pipeline:

- **Structured filter** — pandas enforces hard constraints (beds, price, sqft, neighborhood, etc.) on the CSV to produce a candidate set.
- **Listings semantic search** — a Pinecone index (dense `text-embedding-3-large` + BM25 sparse) ranks candidates by how well `listing_description` matches the natural-language query.
- **Photo visual search** — a second Pinecone index (CLIP `openai/clip-vit-base-patch32`) ranks listings by visual similarity between query text and listing photos.

All three signals are merged via **Reciprocal Rank Fusion (RRF)** before an LLM generates grounded, cited recommendations.

Real estate agents and home buyers can search in plain English —
"a Victorian with original details near Dolores Park under $1.2M" — and get grounded,
cited listing recommendations.

## Data Sources

> **Listings — synthetic data:** The listings dataset (`data/listings.csv`) was **synthetically
> generated by Claude** to approximate plausible real estate inventory across San Francisco
> neighborhoods. Addresses, MLS numbers, prices, square footage, and listing descriptions are
> entirely fabricated. They are loosely modeled on the character of real SF properties but
> **property details, features, and prices are fictional and likely incorrect**. This dataset
> exists solely to demonstrate the RAG pipeline and must not be used for actual real estate decisions.

> **Photos — Unsplash stock images:** Listing photos (`data/photos/`) are downloaded from the
> [Unsplash API](https://unsplash.com/developers) using search queries for exterior property
> styles, luxury bathrooms, and luxury kitchens. They are stock images **not associated with
> the synthetic listings** — assigned to listings purely to illustrate the photo carousel UI.

## Features

- **San Francisco scoped** — all listings are within SF city limits.
- **Natural-language search** — buyers describe what they want; no rigid filter forms.
- **Hybrid retrieval** — CSV structured filter narrows to hard-constraint candidates; Pinecone semantic search on `listing_description` ranks by intent match within those candidates.
- **Description-first search** — `listing_description` is the primary semantic surface because agents encode details there (micro-neighborhood character, finishes, light, views) that don't appear in structured fields.
- **Self-querying** — GPT-4o extracts hard constraints from the question and converts them to pandas filters + a Pinecone semantic query automatically.
- **Grounded answers with citations** — every recommendation cites the listing IDs it came from.
- **Corrective RAG** — if the first hybrid pass returns weak hits, filters relax and retrieval retries once.
- **Conversational** — LangGraph keeps chat state so buyers can refine ("same but with a garage").
- **Two audiences, one app** — buyer chat mode and agent dashboard mode.

## Quick Start

### 1. Prerequisites

- Python 3.10+
- A [Pinecone](https://www.pinecone.io/) account + API key (two serverless indexes required)
- An [OpenAI](https://platform.openai.com/) API key (LLM + embeddings)
- An [Unsplash](https://unsplash.com/developers) API key (photo downloads)

### 2. Install

```bash
pip install -r requirements.txt
```

### 3. Configure

```bash
cp .env.example .env
# fill in your keys and CSV path
```

`.env` keys:

```dotenv
OPENAI_API_KEY=sk-...
PINECONE_API_KEY=pcsk_...
PINECONE_INDEX_NAME=sf-real-estate-listings
PINECONE_PHOTOS_INDEX_NAME=sf-real-estate-photos
PINECONE_CLOUD=aws
PINECONE_REGION=us-east-1
OPENAI_LLM_MODEL=gpt-4o
OPENAI_EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSION=3072
CLIP_DIMENSION=512
LISTINGS_CSV_PATH=data/listings.csv
PHOTOS_CSV_PATH=data/listing_photos.csv
PHOTOS_DIR=data/photos
UNSPLASH_ACCESS_KEY=...
```

### 4. Ingest listings and photos

```bash
# Embed listings into Pinecone (dotproduct index, hybrid search)
python scripts/ingest.py --source data/listings.csv

# Download Unsplash photos and assign to listings
python scripts/fetch_photos.py

# Embed photos into Pinecone (cosine index, CLIP)
python scripts/ingest.py --photos-only
```

The listings ingest embeds `listing_description` with `text-embedding-3-large` and stores
structured columns as Pinecone metadata. Idempotent — re-running updates in place.
Use `--recreate` to wipe and rebuild either index from scratch.

### 5. Run the app

```bash
streamlit run app.py
```

Open http://localhost:8501.

## How a Search Works

```
User question: "3+ bedrooms under $2 million with white kitchen cabinets and marble countertops"
   |
   v
[parse]     GPT-4o extracts hard filters:
              bedrooms_min=3, price_max=2000000
            + semantic query:
              "white kitchen cabinets marble countertops renovated kitchen"
   |
   v
[retrieve — hybrid + CLIP, run in parallel]
   |
   ├─ CSV filter:      pandas filters listings.csv → bedrooms >= 3 AND price <= $2M
   │                   → candidate listing_ids (e.g. 2000 rows → ~380 candidates)
   │
   ├─ Pinecone listings index (dotproduct, hybrid):
   │     dense embed (text-embedding-3-large) + BM25 on semantic query
   │     scoped to candidate listing_ids → top-k hits ranked by listing_description match
   │     signal: [listings-hybrid]  dense ~70% + BM25 ~30%
   │
   └─ Pinecone photos index (cosine, CLIP):
         CLIP text embed "white kitchen cabinets marble countertops"
         → top matching kitchen photos → resolved back to listing_ids
         signal: [photos-clip]  cosine similarity on 512-dim CLIP vectors
   |
   v
[RRF merge]   Reciprocal Rank Fusion merges listings-hybrid + photos-clip rankings
              → unified listing ranking that rewards hits from both signals
   |
   v
[grade]     GPT-4o-mini checks each merged hit for true relevance
            → weak results? relax price_max by 10% ($2M → $2.2M), retry once
   |
   v
[generate]  GPT-4o writes recommendations grounded ONLY in retrieved listings,
            citing each listing_id  [MLS: ...]
   |
   v
Streamlit: answer text + listing cards with photo carousel
```

Full node/state details: [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## Notes

- **SF only:** the app filters and UI copy assume San Francisco. Expanding geography means
  adding `city` / `zip_code` filters and updating the self-query parser.
- **Schema:** the CSV column list is TBD. Once the schema is confirmed, `src/models.py`
  and `src/retrieval/csv_filter.py` will be wired to those exact column names.
- **Grounding:** the generation prompt forbids inventing listings; if retrieval returns
  nothing, the assistant says so.
- **Data in source control:** `listings.csv`, `listing_photos.csv`, and `data/photos/` are
  committed. Only `data/bm25_model.json` (build artifact) is gitignored.
